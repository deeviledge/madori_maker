# 事業計画スタジオ（間取りメーカー）

賃貸併用住宅の **間取り作成 → コスト → 融資 → 収支 → 出口** までを 1 画面で検討するツールです。
1 枚の HTML だったものを **PWA（インストールできる Web アプリ）** にし、スマホのホーム画面から
アプリとして・オフラインでも使えるようにしています。

- データはすべて **端末内（localStorage）** に保存されます。サーバーへは送信されません。
- 通信が切れていても起動・編集・保存ができます（初回だけオンラインが必要）。

---

## 使い方（インストール）

公開 URL を開いて、ホーム画面に追加するだけです。

| 端末 | 手順 |
| --- | --- |
| iPhone / iPad | **Safari** で開く → 共有ボタン <kbd>􀈂</kbd> → **「ホーム画面に追加」** |
| Android | **Chrome** で開く → 画面下に出る「追加」ボタン、またはメニュー → **「アプリをインストール」** |
| PC（Chrome / Edge） | アドレスバー右の **インストールアイコン** をクリック |

追加後はアドレスバーのない全画面で起動し、機内モードでも使えます。

> iPhone では **Safari で開いた場合のみ** ホーム画面に追加できます（Chrome アプリからは不可）。

### 更新について

新しいバージョンを配信すると、アプリ内に「新しいバージョンがあります」というバーが出ます。
**「更新する」** を押すと最新版に切り替わります。保存済みのデータはそのまま残ります。

## 公開する（GitHub Pages）

セットアップ済みです。**`main` ブランチに push すれば自動で公開されます**
（`.github/workflows/pages.yml`）。

公開URL: **https://deeviledge.github.io/madori_maker/**

設定内容（変更したいとき用のメモ）:

- Settings → General → Default branch = `main`
- Settings → Pages → Source = **GitHub Actions**
- リポジトリは public（GitHub Pages を無料プランで使うため）。
  入力した土地・収支のデータは端末内（localStorage）にしか保存されないので、公開されるのはコードだけです。

デプロイのたびに Service Worker のキャッシュ名へコミットSHAが刻印され、古いキャッシュは自動で破棄されます。
利用者側には「新しいバージョンがあります」のバーが出ます。

> PWA（ホーム画面追加・オフライン）は **HTTPS でのみ有効** です。
> ファイルをダブルクリックして `file://` で開いた場合、アプリ自体は動きますが Service Worker は登録されません。

## ローカルで動かす

`file://` ではなく、簡易サーバー経由で開いてください。

```bash
python3 -m http.server 8000
# → http://localhost:8000/ を開く
```

  07-ui-parts.js           フォーム部品・SVGチャート・レンダリング統括
  08-inspector.js          インスペクタ・この階の内訳・建物ビュー

### コードの触り方（重要）

元の 1 枚 HTML をそのままファイル分割しただけで、**ビルドは不要**です。
`js/*.js` は普通の `<script>` として上から順に読み込まれ、関数や変数は
これまでどおりグローバルに共有されます（ES モジュール化していません）。

そのため、次の 2 点だけ守れば安全に編集できます。

1. **`index.html` の script の並び順を変えない**（後ろのファイルが前のファイルの関数を使う前提）
2. **起動処理は `js/99-boot.js` に置く**（全ファイルが読み込まれた後に実行する必要がある）

新しい JS / CSS ファイルを増やしたら、オフライン用のキャッシュ一覧も更新します。

```bash
node tools/update-sw-precache.mjs          # sw.js の CORE を index.html から作り直す
node tools/update-sw-precache.mjs --check  # ずれていないか確認だけ（CIで実行）
```

アイコンを描き直したいときは `icons/favicon.svg` / `icons/maskable.svg` を編集し、
任意のツールで 192 / 512 px の PNG を書き出して `icons/` に置き換えてください。

### 分割前の1枚HTMLが必要なとき

最初のコミットにそのまま入っています。

```bash
git show $(git rev-list --max-parents=0 HEAD):madorieditor-v43.html > madorieditor-v43.html
```

- 全 9 タブ（間取り／建物／土地／コスト／融資／収支／計画／出口／比較）の描画が、分割前の 1 枚 HTML と一致

## 図面の表示（設計図面モード）

表示シート（画面右上 ☰ → 表示）の **「設計図面」** をONにすると、平面図が建築図面の書式になります。

- 通り芯（一点鎖線）と **X1・Y1…** の符号
- 外側2段の寸法線（**総寸法** と **通り芯間**）
- 壁のソリッド塗り（外壁＝濃／内壁＝淡）と、隅の柱
- 方位マーク・図面枠・表題欄（シナリオ名／階／床面積／建物枠／日付）
- 線幅の階層（断面線＝太、設備の姿線＝細、寸法・補助線＝極細）と、部屋名＋畳数の書式

方位マーク（N）の向きは **建物タブ →「方位（北の向き）」** で変えられます（図面の上を0°として時計回り）。
図面の見た目だけで、日照・採光の計算には使っていません。

**見た目だけの切り替えです。** 面積集計・法規判定・収支の数値には一切影響しません
（切替前後で床面積・建築面積が一致することをテストで確認しています）。
柱は作図上の表現で、構造計算に基づくものではありません。

### 全階の平面図PDF

出力シートの **「📐 全階の平面図PDF（設計図面）」** で、**1階＝1ページ**のPDFを出せます。
画面と同じ描画関数（`paintPlan`）を通しているので、**画面で見えている図面がそのまま出ます**。
全タブまとめPDF・銀行提出用PDFの平面図も、この描画に揃えてあります。

## 床面積がどこに入っているか

**床面積（延床）に入るのは「部屋」として置いた範囲だけ**です。階段・家具などの「設備」は
絵は出ますが延床には入りません（`floorTotalsSc` が `gross` に加算するのは `f.rooms` のみ。
設備の `areaMode` は容積・建ぺいの基礎数値だけを増減します）。

表示シートの2つのトグルで、そこが目で見えるようにしています。

- **未算入** … 建物枠の中で、**どの部屋にも覆われていない範囲**を赤いハッチで塗ります。
  「この階の内訳」にも「枠内で床になっていない ○○㎡」を出します。
- **下階** … ひとつ下の階の部屋の輪郭を**茶色の破線**で透かして重ねます。
  階段の上部や吹抜けが「上階の床か下階の床か」を見ながら組めます。

設備の範囲を床として算入したいときは、その設備を選び、インスペクタの
**「設定（種別・算入）」タブ → 床面積への反映** で範囲を選んでから
**「▦ この範囲を部屋にする（床面積に算入）」** を押します。

範囲は **全体 / 上半分 / 下半分 / 左半分 / 右半分 / 階段の実寸** から選べ、
押す前に追加される㎡と寸法が出て、平面図にも破線でプレビューが出ます。

階段は **下の階では階段室ぜんぶが床、上の階では上りきった側だけが床**（残りは吹抜け）
になります。全体のまま各階で部屋にすると床を二重に数えてしまうため、上の階では
「上半分」などに絞ってください。「階段の実寸」は `stairCalc` の run（段が並ぶ長さ）×
clearW（有効幅）＝1経路ぶんの範囲です。

## 選択バーの位置

部屋や設備を選ぶと出る操作バーは、既定で **上のツールバーのすぐ下に固定**されます
（`pos-top`）。図面の上に浮かないので、間取りが隠れません。

バー左端の **⇄** で **上に固定（横）/ 左端（縦）/ 右端（縦）/ 下（横）** を切り替えられます。
上と下は横並び、左右は縦並びです。

### 微調整パッド

「微調」「変形」モードで出る位置・サイズの調整パッドも、既定で **選択バーのすぐ下に固定**されます
（上のメニュー → 選択バー → 微調整パッド → 図面 の順）。9つのボタンが1行に並び、
360px 幅の端末でも「×」まで収まります。

パッド左端の **✥（位置 ≡）** で **上に固定 / 右下 / 左下 / 左上 / 右上** を切り替えられます。
浮かせるモードでは従来どおりドラッグで自由に動かせます（上に固定のときはドラッグしません）。

## 壁の自動整列

手で置いた部屋は 7198 と 7200 のように数ミリずれることがあります。
表示シートの **「⌗ この階を整列 / 全階を整列」** で、近い座標どうしを1つに寄せて一括で直します。

- 許容するズレは 30 / 60（標準）/ 100 / 150 mm から選べます。許容外の差は動かしません
- 建物枠（0・間口・奥行）は寄せ先として最優先されます
- 寄せ先は **部屋の頂点と建物枠だけ**から作ります（家具の座標で壁が引っぱられないため）
- 実行前に「何箇所そろえるか」を確認でき、実行後は延床の変化量を表示します
- **↩（元に戻す）で戻せます**

### 設備の扱い

- **ドア・窓** … 整列のたびに**必ず壁の上へ乗せ直します**。壁と直交する方向だけ動くので、
  **壁沿いの位置と向きはそのまま**です
- **ソファなどの家具・階段** … **既定では動かしません**。壁にかかっていても実用上は困らないのに対し、
  勝手に動くほうが困るためです。表示シートの
  **「家具・階段も部屋に合わせて動かす」** をONにすると、その部屋が動いたぶんだけ追従します

### 開口部だけを壁に合わせる

表示シートの **「🚪 開口部を壁に合わせる / 全階の開口部」** で、ドア・窓だけを最寄りの壁へ乗せ直せます。
整列しなくても単独で使えます。

**ドア・窓は追加した時点でも自動で壁に乗ります**（追加のときだけ探索範囲を3mに広げ、
向きもその壁に合わせます）。

### 階の並べ替えと入れ替え

フロア管理シート（間取りタブの「追加・編集」）で2種類を使い分けます。

- **▲▼** … 階の順番を動かす（**階名も一緒に動きます**）
- **⇅** … **間取りの中身だけを入れ替える**（階名はその場に残る）。
  「1Fと2Fの間取りを入れ替えたい」はこちら。⇅ を押してから、入れ替え先の行の「ここと入替」を押します。
  部屋・設備・建物枠がまとめて入れ替わり、↩（元に戻す）で戻せます。

## 税・ローンの計算について

- **借入形態**は融資タブで 単独／収入合算／**ペアローン** を選べます。
  ペアローンは「借入割合＝持分」とみなし、**住宅ローン控除・不動産所得の損益通算を各自別々に**計算します。
- **税率は年収から自動計算**します（給与所得控除 → 社会保険料・所得控除 → 課税所得 → 所得税速算表＋住民税10%）。
  手入力に切り替えることもできます。
- **住宅ローン控除は各自の税額で頭打ち**になります（所得税額＋住民税からの控除上限＝課税所得の5%・最大9.75万円）。
  年収が低いと残高×0.7%を使い切れないため、収支タブ④に満額と実際に使える額の内訳を出しています。
- 未反映：青色申告特別控除・事業税・消費税・社会保険料の増減・定額減税などの単年度特例・所得金額調整控除。
  ペアローンの**金利と返済年数は2人共通**（採用プランの条件）で、残高は借入割合で按分しています。
- いずれも概算です。実際の申告・審査は税理士および金融機関に確認してください。

## 制限事項

- **Excel 出力**はオフラインだと外部ライブラリ（SheetJS）を取得できないため、自動的に **CSV** で書き出されます。
  一度オンラインで Excel 出力を実行しておけば、以降はオフラインでも Excel 形式で出力できます。
- **PDF 出力**は印刷ダイアログ方式です。iPhone では共有メニューから「PDF として保存」を選んでください。
- Web フォントは初回オンライン時にキャッシュされます。取得前はシステムフォントで表示されます。
- 判定はいずれも簡易計算です。角地緩和・日影規制・地区計画などは未反映のため、
  最終判断は必ず役所窓口・重要事項説明で確認してください。
